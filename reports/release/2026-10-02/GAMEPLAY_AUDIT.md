# Независимый разбор логики и UI/UX — 2 октября 2026

Проверяемая исходная версия: `d9ecb43791fa89a0b3196fe32c85f975e8d63157`, main после PR #51. Проверка выполнена заново по коду, каноническим спецификациям и реальному вводу в Chromium. Зелёный предыдущий smoke не считался доказательством исправности переходов: он перезагружал страницу между работами и не проверял выход из казино.

Связь с существующим backlog: T051/T052/T053 (мини-игры), T057 (casino UI), T059 (обучение), E08 (безопасное продолжение Plinko). Отчёт фиксирует результаты проверки, не заменяет BACKLOG.md.

## Вывод

Основные проблемы были в жизненном цикле сцен и несоответствии поведения интерфейса механике. Пользователь мог застрять в казино, повторная смена могла перестать завершаться, а курьер вообще не двигался. Это блокеры плейтеста, а не косметика. Исправления продолжают существующую реализацию; экономика, стоимости, шансы, долг, ограничения работ и версия сохранения не менялись.

## Поведение новых механик

### Курьер

Игрок рисует линию, может один раз её очистить, нажимает START и смотрит движение. Редактирование после старта запрещено. Первый контакт габаритов персонажа с препятствием фиксирует поражение в точке столкновения — будущий опасный участок не вызывает поражения заранее. Если линия заканчивается внутри зоны доставки, короткий последний отрезок доводит персонажа до её центра; если снаружи — он доходит до конца линии и проигрывает. Barry останавливает рабочую сцену через существующие часы; деньги начисляются через прежний `completeWorkSkill`, а не из анимации.

Скорость 240 logical px/s, коллайдер 58×58 и размер маски грязи — параметры взаимодействия/представления в model, не новые экономические правила. Скорость ещё требует человеческой оценки удобства. Обводки ящиков обозначают их препятствующую область; нужно учитывать ширину курьера, а не только тонкую линию.

### Посуда

Грязь — зернистая сплошная плёнка внутри тарелки. Удержание мыши/пальца стирает её, включая промежутки между редкими событиями ввода. Прогресс считается по площади одинаковых ячеек маски, а не по числу декоративных пятен. Маска обновляется только при изменении грязи; таймер не перезагружает текстуру каждый кадр. Порог 90%, лимит 20 секунд, штрафы и выплата остались прежними.

## Что остаётся открытым

1. **Производительность Plinko — P1 для релиза.** Исторический строгий CPU×4 gate не пройден. Этот проход не выдаёт его за пройденный и не ослабляет пороги. Каскадные пассивные минуты привязаны к фиксированным тикам ради сохранения фазы при reload; соответствие wall-clock на сильно проседающем FPS нужно измерить вместе с исправлением fixed-step runtime.
2. **Мобильная читаемость — P2.** Основные перекрытия устранены, но при уменьшении 1280→640 часть цен, причин блокировки и подписи карманов остаются мелкими. Нужен плейтест на физическом телефоне, затем адаптация плотности информации; один desktop touch-эмулятор этого не доказывает.
3. **Длина и сложность работ — P2.** Автотест может отмыть тарелки или проложить обход быстро. Целевые 15–30 секунд, интерес маршрутов, скорость курьера и понятность штрафа требуют человеческого плейтеста. Не менялись выплаты/таймеры ради прохождения smoke.
4. **Помойка — P2.** В коде действие и результат применяются сразу; описанная в MINIGAMES_SPEC тактильная анимация 2–4 секунды отсутствует. Это отдельная недостающая презентация, не исправленная новым курьером/посудой.
5. **Ошибки записи — P1 для hosted-приёмки.** Существующие Promise-цепочки не имеют полноценного retry/UX восстановления после отказа storage. Проверки этого прохода подтверждают успешные записи и reload, а не отказ cloud storage/квоты браузера.
6. **Реальный Yandex SDK, реклама/cloud, native-resolution art и полный 30-минутный баланс** сохраняют прежние открытые release gates. Pages остаётся плейтестом с localStorage, не принятой RC.

Следующий полезный ручной проход: свежий забег → одна работа → казино → выход при движущемся шаре → повторный вход → ещё одна та же работа → подход к 09:00. Для новой посуды стоит отдельно проверить короткие движения пальца у края тарелки; для курьера — узкий проход и столкновение боком персонажа.
